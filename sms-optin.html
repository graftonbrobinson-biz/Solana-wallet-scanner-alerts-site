SMS Opt-In

Who can receive alerts, how consent works, message frequency, and how to stop.

There is exactly one recipient

This program has a single authorized recipient: the person who owns and operates this application. It is not open for public sign-up. There is no web form on this site (or anywhere else) that adds a new phone number to this program. The sending number, +1 (401) 394-7520, only ever sends to the one number the operator has configured for their own use.

What you are consenting to receive

By opting in, the recipient agrees to receive automated text message alerts about:

  • BUY alerts — when enough of the watched wallets buy the same token within a short window of each other.
  • SELL alerts — when those same wallets sell or exit a position, including whether the exit is a confirmed full exit or a partial sell.

These are automated, informational notifications generated by on-chain activity. They are not sent or reviewed by a person before sending, and they are not financial advice (see the Terms & Conditions).

Message frequency

Message frequency varies with on-chain activity and will not exceed 25 messages per day. On many days there may be zero messages. This limit is enforced by the application itself, independent of any per-message cooldown logic.

Message and data rates

Message and data rates may apply. Carrier fees for sending and receiving text messages are the responsibility of the recipient's mobile carrier plan.

How to stop or get help

Reply STOP to any message to stop receiving further messages.

Reply HELP to any message for help, or contact graftonbrobinson@gmail.com.

Verified limitation — please read before relying on this: the application that sends these alerts does not itself run a server that receives incoming text messages, and its source code contains no logic that recognizes the words STOP, START, or HELP. Any keyword handling for this program happens entirely on Twilio's platform, not in this application's own code.

Per Twilio's own documentation (checked here), Twilio automatically handles STOP (and its synonyms UNSUBSCRIBE, CANCEL, END, QUIT, STOPALL, REVOKE, OPTOUT), START/UNSTOP, and HELP by default on long code numbers, without requiring "Advanced Opt-Out" to be turned on — Advanced Opt-Out is a separate, optional feature only needed to add custom keywords or customize the automatic reply text. STOP, START, and HELP are documented as reserved keywords that always work even when Advanced Opt-Out is used to customize other things.

How consent is given (opt-in process)

Because there is only one recipient and no public sign-up form, this program does not use an automated web opt-in flow. Instead, enrollment is enforced structurally, in the application's own configuration:

  • The application will only ever send a message to a phone number that the recipient has personally entered into their own private configuration (an environment variable the application reads on startup). This is the single, sole mechanism by which a number is added — there is no other code path, database, or public form that can add a recipient.
  • Because the recipient and the operator are the same person, entering their own number into that configuration is the act of opting in: no one else can opt a number in on someone else's behalf, and no number is ever added without the recipient directly and deliberately doing so themselves.
  • Removing the number from that configuration, or disabling the program entirely (the recipient controls both), immediately and permanently stops all messages — this does not depend on Twilio, a reply keyword, or any third party.
